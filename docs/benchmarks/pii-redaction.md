## What is measured

The benchmark runs the production code path — `prepareText` → `PiiDetectionService` →
`MaskingSession.mask` → `findLeaks` (the gateway's egress check) → `unmask` — over a
synthetic corpus generated from seed 20260924:

| Category | Documents |
| :--- | ---: |
| chat | 294 |
| clean | 205 |
| finance | 277 |
| hr-record | 509 |
| it-incident | 304 |
| support-ticket | 411 |

Documents are written the way the data arrives: HR records, support tickets, IT incident
notes, informal chat, payment instructions, and clean notices with no personal data at all.
Values come in the formats people actually use — Pakistani mobiles with and without the
`0092`/`+92` prefix, grouped and compact cards and IBANs (some lower-case), amounts with
symbols, codes, "lakh", "k" and in words, plus-addressed emails, vendor keys and passwords in
connection strings. 4.8% of entities
(980) are **obfuscated** in the source text — full-width digits,
zero-width spaces between characters, no-break spaces — and every document carries **decoys**
(12,191 in all) that look like personal data and are not: order and tracking numbers
(16 digits, Luhn-invalid), dates, ISBNs, invoice and employee IDs, version strings, commit
hashes, prices, fees, years, percentages, phone extensions.

Two separate scores:

- **Detection** — precision, recall and F1 per entity type. A detection counts if it
  overlaps an annotation *of the same type*.
- **Protection** — whether every non-space character of an annotated value ended up inside
  a placeholder, whatever the type. This is the privacy number: a card masked as a phone
  number is a type error, not a leak.

Configuration: entity types `CREDENTIAL`, `CREDIT_CARD`, `CUSTOM`, `EMAIL_ADDRESS`, `IBAN_CODE`, `IP_ADDRESS`, `PHONE_NUMBER`, `PK_CNIC`, `SALARY`, `US_SSN`;
score threshold 0.5; deny list "Project Falcon", "Operation Blue Heron", "Codename Nimbus".

## Round trip

Unmasking restored the same entity at every masked span in 2,000 of
2,000 documents, and character-for-character in 1,995. The
difference is by design: one value written two ways ("Rs. 280,000" and "PKR 280,000") is one
entity with one placeholder, restored in one form, and a surname linked to a full name is
restored as the full name. Streaming the masked text through the unmasker in random 1–8
character chunks gave output identical to unmasking it whole in 2,000 documents.

## Measuring names

Person names are the one type patterns cannot find; they need the NER model the AI service
(or a Presidio analyzer) runs. With one configured:

```bash
AI_SERVICE_URL=https://ai.example.com AI_SERVICE_SIGNING_SECRET=… npm run benchmark:pii -- --ner ai-service
PRESIDIO_ANALYZER_URL=https://presidio.internal npm run benchmark:pii -- --ner presidio
```

writes `pii-redaction-<ner>.md` beside this report, with PERSON measured and the NER round
trip in the latency table. Linking and propagation then extend each name the model finds to
its other mentions ("Raza" after "Ayesha Raza"), which is where most of the name recall
beyond the raw model comes from.

## Limitations

- **The corpus and the recognizers were developed together.** Every format in the corpus is
  one the engine is designed to handle, and the benchmark was used to find and fix its
  mistakes (see the regression tests in `recognizers.spec.ts` and
  `masking-session.spec.ts`). Perfect recall here therefore means *no regressions on the
  formats it knows*, not *finds everything*: a format absent from the corpus is not measured.
- **Synthetic text.** Real documents are messier: OCR noise, tables flattened into prose,
  numbers split across lines. The corpus is designed to be hard in the ways that matter
  (obfuscation, look-alikes) but is not a substitute for a labelled sample of real data,
  which a deployment should evaluate before relying on the figures.
- **Context heuristics cut both ways.** Salary detection needs a compensation word near
  the amount, so an amount far from one is missed, and a number near one — an annual fee,
  an order number in a payroll email — can be masked. The decoy table shows the rate.
- **Recall is not the last line.** A value the detector misses in one place is still masked
  wherever the same value was detected elsewhere in the prompt (propagation), and the
  gateway re-scans every outgoing prompt; but a value no stage recognises anywhere leaves.
  That is why the default policy refuses to send anything when the NER model is down.
